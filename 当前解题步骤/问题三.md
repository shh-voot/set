# 问题三：运输与通信中继协同

## 1. 输入

读取问题二的49架次调度、官方通信链路参数、30 m DEM、调度中心和服务区坐标，以及官方R01/R02中继无人机和6组能源组件。

## 2. 直连与候选中继判定

沿调度中心到服务区的完整路径采样。对每条链路进行双向链路预算：

- 使用DEM进行地形视距判断；
- 仅在DEM判断遮挡时加入官方障碍损耗；
- 同时满足正向和反向接收灵敏度、系统损耗和安全裕度约束。

在服务区范围内建立21×21候选网格，计算每个候选位置可覆盖的服务区集合和中继飞行、悬停能耗。

## 3. 中继部署

由于官方只有R01和R02两架中继，使用二中继联合集合覆盖搜索，而不是无限增加中继。候选组合优先覆盖更多非直连服务区，再比较能源组件数量、建链时间和能耗。

## 4. 联合时间调度

计算每架中继的准备、飞行和建链时间，形成服务开始时间。对依赖中继的运输架次重新按截止时间排序，并使用官方A/B/C机型参数重新分配可行机型，避免运输任务早于中继建链或超出服务窗口。

## 5. 中继能源核验

按中继往返飞行能耗和服务悬停能耗拆分能源组件，使用官方组件容量、备用比例和充电时间，检查组件总数不超过6组。

## 6. 当前结果

- R01/R02：2架官方中继；
- 服务区覆盖15/15，覆盖率100%；
- 运输通信可用49/49架次；
- 80箱无迟到；
- 中继能源组件4/6组；
- 运输完成213.9877 min；
- 含中继返航的联合完成时间222.8113 min；
- 联合总能耗114.3686 kWh。

当前问题三在可行性指标上已满足全部覆盖和通信要求，但仍可优化联合目标：候选中继位置目前按固定网格搜索，且两中继任务分区采用覆盖集合映射，尚未对部署位置、服务区分配、运输机型/架次和中继服务时长做完整全局联合优化。后续优化应保留100%覆盖、49架次通信和全部截止时间为硬约束，再比较联合完成时间与总能耗；不能以降低覆盖或跳过官方链路预算换取表面性能改善。
