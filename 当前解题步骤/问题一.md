# 问题一：单架次配送组批

## 1. 输入

读取官方货箱、服务区、调度中心、运输无人机参数和30 m DEM。每个货箱只允许被配送一次。

## 2. 单架次模型

对每个候选机型和货箱组，依次校验：

1. 总质量不超过机型最大载荷；
2. 总体积不超过机型最大容积；
3. 依据DEM航段最高地面高程确定巡航高度；
4. 计算爬升、巡航、下降和返航能耗；
5. 计算交付时间、总任务时间和等效航程；
6. 校验可用电量和返航安全余量。

## 3. 组批算法

采用按服务区分组的Best-Fit/First-Fit Decreasing思路：先按货箱重量和体积排序，再尝试将货箱加入已有架次；只有通过官方载荷、体积、DEM能耗和等效航程校验时才接受，否则新建架次。

## 4. 全局校验

- 货箱编号去重后必须为80个；
- 所有官方货箱必须被覆盖；
- 每个架次必须满足 `feasible=True`；
- 逐架次检查能量余量和航程余量；
- 对官方截止时间做逐箱时限检查。

## 5. 时间优化

在保持18架次、80箱唯一覆盖和全部物理约束可行的前提下，增加了“最长架次任务时间”局部优化：在同一服务区内尝试跨架次移动货箱，仅接受不增加架次数且能降低最长任务时间的移动。该优化不改变官方输入数据，也不放宽载荷、体积、能量或航程约束。

## 6. 当前结果

- 18架次；
- 80箱唯一覆盖；
- 0箱迟到；
- 最长单架次任务时间38.6048 min；
- 架次时间总和约550.0312 min；
- 总能耗约56.5159 kWh。

该版本降低了最长单架次时间，但总能耗略有增加，因此如果论文目标优先考虑总能耗，应保留原18架次方案；如果问题一强调时效，则采用当前时间优化方案，并明确多目标权衡。

注意：18架次是配送架次，不是18架实体无人机；问题一尚未加入实体机和共享电池并行调度。
