## 当前重算结果

### 问题一

18 架次、80 箱唯一覆盖，所有架次通过当前载荷、体积、能量和航程检查；总能耗 **54.2159 kWh**。旧的 56.5159 kWh 属于线性航程和旧 DEM 取值口径，不再作为正式基线。

### 问题二

采用截止时间优先、候选组批、有限宽度束搜索和局部交换搜索，得到 **45 架次**；系统完成时间 **172.1842 min**，总能耗 **94.4917 kWh**，80 箱按时。结果文件为 `结果/问题二_增强优化版.xlsx`。旧的43架次、171.5840 min和93.8540 kWh来自旧公共模型。

### 问题三

严格使用服务区地面高程加30 m作为投送通信端点，并按“直连不可用的路径采样点”计算中继覆盖。0926 联合窗口版允许官方可行机型替换，并联合优化运输开始时间、中继服务窗、返场和周转。正式结果达到 **45 架次、80/80 箱、0 迟到、10890/10890 通信采样点可用**；使用3个中继服务窗口和3组官方能源组件，运输完工 **166.00 min**，联合完工 **199.3866 min**，总能耗 **100.4448 kWh**。正式文件集中在 `0926解题思想/`，由 `代码/q3_finalize_formal.py` fail-closed 核验生成。

### 问题四

问题四已改为读取问题三的联合任务，不再读取问题二的旧任务。按题意各任务组从各自时钟零点独立执行，继承的运输交付没有新增迟到：2批次和3批次均为 **0箱迟到**；资源缺口分别见 `结果/问题四_2批次_修复版.xlsx`、`结果/问题四_3批次_修复版.xlsx`。此前把各组强行串行拼接的65箱迟到只保留在 `问题四_错峰复用汇总.json` 的 sensitivity 字段中，不作为问题四正式指标。由于问题三联合通信输入仍不可行，问题四的 `feasible_official_inventory` 仍为 false。
