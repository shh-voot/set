# 优化方案设计

## 1. 基线

基线使用 `解题-gpt/代码/solve_problem2_lns.py`：按服务区和官方截止时间分组，使用官方 DEM `direct_mission` 产生可行组批，再用有限宽度束搜索和局部换型确定 A/B/C 类型，最后用共享电池离散事件模型调度。重新运行得到 43 架次、173.7274 min、95.2042 kWh、0 箱迟到。

## 2. 优化对象

本轮只优化已生成架次的执行顺序。这样可以把改进归因于资源调度，而不会把未经核验的多点路径或虚构参数混入模型。每个架次的服务区、货箱集合、机型、能耗、飞行时间和配送偏移均保持不变。

## 3. ALNS 顺序搜索

先按官方截止时间形成 60、120、180、240、300 min 五个时间层。一次邻域操作只在一个层内破坏和修复：

1. 随机移除 2–5 个架次；
2. 破坏算子按随机架次、作业时长较长架次、能耗较高架次或充电负担较大的架次选择；
3. 修复算子分别按配送偏移、作业时长和能耗排序，并在该时间层的所有插入位置中选当前词典序最优位置；
4. 记录每个破坏/修复算子的改进奖励，按指数平滑更新算子权重，使有效算子被更频繁抽取；
5. 每一个候选都重新执行官方实体无人机、共享电池和两阶段充电离散事件仿真；
6. 只接受严格改善的全局最优解，或接受不劣于当前解的候选以保持搜索多样性。

词典序目标为：

\[
 (N_{late},\;T_{late},\;C_{max},\;E_{total},\;N_{trip}),
\]

其中首先要求迟到箱数和总迟到时间为零，然后最小化系统完成时间、总能耗和架次。由于每个候选都进行官方物理核验，ALNS 不能通过牺牲返航余量或库存换取更短时间。

## 4. 为什么只在同层搜索

跨层交换可能把首批保障任务推迟到更严格截止时间之后，也会让调度顺序优化与组批优化混在一起。本轮先锁定组批，仅优化同层资源竞争；后续若做跨服务区多点路径，必须重新构造路径并逐架次调用官方 DEM 模型。

## 5. 伪代码

```text
S ← 当前正式架次顺序
best ← SimulateOfficial(S)
repeat I 次：
    选择一个截止时间层和一对自适应算子
    R ← Destroy(S, 2–5 个架次)
    S' ← Repair(R, 三种插入规则)
    y ← SimulateOfficial(S')
    若 Objective(y) ≤ Objective(S)，保留 S'
    按改进奖励更新算子权重
    若 Objective(y) < Objective(best)，更新 best
输出 best
```
