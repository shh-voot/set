# 当前修复状态

本轮所有计算使用 `数据/无人机应急物资运输基础数据` 和 `数据/镇龙乡地理空间数据` 中的官方附件。没有使用 README 中的旧结果，也没有用外部基准替代赛题数据。

## 已完成

- `src/data/data_loader.py`：修正运输机最大载荷、实体数量、共享电池数量和充电时间读取。官方值为 A/B/C 载荷 25/30/80 kg，实体 4/2/2 架，电池 6/4/4 组，等效完全充电时间 30/40/50 min；中继实体 R01/R02，能源组件 6 组。
- `src/energy/energy_model.py`：安全余量字段统一为比例，并使用空载/满载等效航程插值使载荷进入水平巡航能耗。
- `solve_problem1_18trips.py`：改为官方逐箱清单、30 m DEM 航段最高地面高程、爬升/巡航/下降三阶段能耗和返航余量校验。输出 `结果/问题一_18架次方案_修复版.xlsx`。
- `solve_problem2_fixed.py`：基于问题一修复版组批，按官方实体无人机、电池和两阶段充电模型做离散事件排程，输出逐箱交付时刻和时限校验。输出 `结果/问题二_修复版.xlsx`。
- `solve_problem2_optimized.py`：结合异构VRPTW、最早截止期优先和无缺货电池调度文献思路，重新允许机型选择和按截止时间组批；输出 `结果/问题二_优化修复版.xlsx`。
- `solve_problem3_relay.py`：接入修复版问题二，按官方通信链路参数、30 m DEM 视距、双向链路预算、R01/R02 和能源组件数量搜索中继部署；无法达到100%覆盖时如实报告不可行。输出 `结果/问题三_*_修复版.xlsx/json`。
- `solve_problem4_fixed.py`：保持问题三架次和通信覆盖关系，按2组和3组分别固定时刻重算峰值实体机、电池、充电桩和中继能源组件，并给出相对官方库存的缺口。输出 `结果/问题四_2批次_修复版.xlsx` 和 `结果/问题四_3批次_修复版.xlsx`。

## 当前官方数据运行结果

- 问题一：18 架次，80 个唯一货箱，所有架次通过能量和等效航程安全校验，总能耗 54.8271 kWh。
- 问题二（重新优化版）：49 架次，80 个唯一货箱，完成时间 205.615 min，总运输能耗 106.2827 kWh；80箱全部按官方截止时间完成。方案使用A4/B2/C2架实体机和A6/B4/C4组共享电池，未超库存。
- 问题三、问题四已在问题二重新优化方案上重新运行；旧的基于18架次/旧问题二的覆盖和分区数字不再作为最终结果。
- 问题三最终结果：R01/R02联合部署覆盖15/15个服务区，覆盖率100%；49/49个运输架次通信可用，80箱无迟到。中继能源组件使用4/6组；运输能耗106.8941 kWh，中继能耗7.4744 kWh，联合能耗114.3686 kWh；运输完成213.9877 min，中继返航计入后的联合完成时间222.8113 min。
- 基于该方案的问题四：2组独立执行需要A/B/C实体机4/2/4架、共享电池6/4/5组，缺2架C型机和1组C型电池；3组需要A/B/C实体机5/4/5架、共享电池7/6/6组，缺A1、B2、C3架及A1、B2、C2组电池。中继均按R01/R02和4组能源组件独立核算。

## 解释

问题一按单架次模型的最长任务时间为39.3478 min，18架次任务时间总和为548.5846 min；问题一没有实体机/共享电池的并行调度约束，因此不能把总和当作系统完成时间。问题二在官方实体机和共享电池事件调度下的完成时间为205.6148 min，49架次、80箱全部按时完成。后续若改变组批或机型分配，必须重新运行货箱唯一性、载重、DEM能耗和安全余量核验，不能直接替换结果数字。
